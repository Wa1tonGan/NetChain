# De-hardcode the frontend recovery flow, wire it to the real backend, and drop unused pages

## Findings (analysis summary)

Commit `897b54a` (plus follow-ups `b4f000b`, `58b27a6`, `4832cb9`) rewrote `frontend/src/components/RecoveryOverlay.tsx` (now 1,037 lines) into a **time-scripted fake conversation**: messages appear at hardcoded `sec >= N` thresholds, with fixed bids (Maxis 500 Mbps/USDC 2.20, Digi 450/1.95, KilatLink 500/1.80), fabricated Gonka votes (fake models "DeepSeek-V4-Flash"/"MiniMax-M2.7", fake request IDs), fake radio telemetry (−72 dBm/SINR 24 dB), regex rewrites of thread text, and `|| 500` fallbacks. Supporting hardcodes: `flows.ts` `autoSend: "500 Mbps, USDC 2"`, `useAppStore.ts` SMS hints, `HomePage.tsx` (scripted "Agent activity" feed, recovered metrics `latency 18 / loss 0.0 / max(current,500)`).

The backend already produces everything real the modal needs, and `useAppStore.ts:994-1572` already implements the live client flow (`submitIntent` → SSE `/incidents/:id/events` → adopt result → `POST /v1/commit` → activation → SETTLED row). But that live path is **unreachable from the main UI today**: HomePage triggers the simulated `startRecovery("auto", 500)`, the SMS composer was removed from the overlay, and live runs stall at the SMS stage. The live machine also never sets `incident.commitTxDigest/settleTxDigest/walrusBlobId`, so the overlay's real links never appear.

**Decisions (defaults, questions were skipped):** backend-first with simulated fallback; render only fields the backend really provides; keep `dummyUsers` as demo data with computed KPIs.

## Implementation

### 1. Remove Services + Truth Agent pages (new request)
- Delete `frontend/src/pages/ServicesPage.tsx` and `frontend/src/pages/TruthAgentPage.tsx`.
- `App.tsx`: drop their imports (lines 9, 14) and the `/services` + `/truth` routes (lines 48, 51).
- `Shell.tsx`: remove the two floating-dock NAV entries ("Services", "Truth") — nav becomes Network / Incidents / Profile.
- Orphan cleanup: `frontend/src/services/market.ts` is used only by ServicesPage → delete; the store's enterprise-services slice (`services`, `serviceSeq`, `seedServices`, `saveService`, `removeService`) and `ServiceItem` type have no remaining consumers → remove. `ClaimAuditCard` / `AgentSteps` / `DecisionCard` stay (Incidents pages use them; audit data still surfaces there).

### 2. Backend — one additive change
`src/agents/rescueAgent.js` (~line 576): the `arrival` SSE event currently emits only `{providerId, receivedAtMs, offerId, pitch}`. Add the offer summary so bid cards show real numbers: `capacityMbps, price, currency, latencyMs, packetLossPercent, reliabilityScore, expectedActivationTimeMs`. Backwards-compatible; no other backend change needed — votes (`model/requestId/ranking`), consensus, settlement, Truth-Agent audit (`CLAIM_VERIFIED` rows, which do include real per-model reasoning/scores) and Walrus archive rows already exist.

### 3. Types & services
- `services/types.ts`: add a `RunLogEntry` union — `alert | intent | bid | consensus(R1) | escrow | telemetry | audit(R2) | restored` — each carrying `{at}` (real event timestamp) plus typed fields.
- `services/live.ts`: extend `GatewayEvent` with the new arrival fields; add `fetchIncidentRecord(id)` for refresh-resilience.
- New `services/intentBuilder.ts`: builds a schema-valid RecoveryIntent from the app's real state (degraded Mbps, demand/shortage, `maxPerRecovery` budget, `maxDuration`), using the matching scenario file as the structural template and computing all cross-validated fields consistently (`usableCapacityMbps`, `requiredCapacityMbps`, `grossShortfallMbps = required − usable`, `recoveryCapacityNeededMbps`, `recoveryDecision`, affected-service deficits summing to the shortfall).

### 4. Store (`useAppStore.ts`)
- Add reactive `runLog: RunLogEntry[]` (reset per run).
- **Auto-dispatch fix**: live runs no longer stall at the SMS stage — the derived reply (`${shortage} Mbps, USDC ${budget}`) auto-sends, then `beginLive` submits the built intent.
- `startRecovery(kind, shortage)` becomes **backend-first**: probe `GET {GATEWAY_URL}/health` (~1.5 s timeout) → healthy: run the live flow with the built intent; unreachable: existing simulated flow. HomePage and the real-outage watcher get this automatically; DevPage keeps explicit sim scenario buttons + "Run live".
- Live machine appends run-log entries as real events arrive:
  - `alert` / `intent` (actual submitted numbers + gateway incidentId),
  - `bid` per `arrival` event (brand via `liveBrand()`, real capacity/price/latency/reliability; winner + rejection reasons from `SELECTED`/`rejection` events),
  - `consensus` from `SELECTED` votes — model name, **real gonka requestId**, `VOTE: <first-ranked brand> ✓`, unanimity computed from rankings; fabricated "Reasoning:" prose dropped (backend doesn't provide it in votes),
  - `escrow` from the commit response — real amount (`offer.agreement.amount`), real `ESCROW_DEPLOY.escrowId`, real `txDigest`; **patch `incident.commitTxDigest`** (missing today),
  - `telemetry` on settle — real delivered capacity, contracted latency/loss from the offer, audit verdict; dBm/SINR lines dropped (no source); **patch `incident.walrusBlobId`** from SETTLED/ARCHIVED rows,
  - `audit` (Round 2) from the `CLAIM_VERIFIED` row already ingested into `claimAudits` — real models, verdicts, scores, requestIds **and real reasoning strings**,
  - `restored` from the real result.
- Simulated machine feeds the same run-log shape from its own data (flows/`BLUEPRINT_PROVIDERS`, `/v1/demo/commit|settle` responses) so the offline fallback renders identically through one renderer.
- Remove hardcoded strings: `flows.ts` `autoSend` literals → derived from shortage+budget; SMS hints → derived; `finishRecovery`'s hardcoded `provider: "KilatLink FWA"` → from market data.

### 5. `RecoveryOverlay.tsx` rewrite (same look, real data)
Keep every visual: step bar, header, bubble layout, special-indicator/escrow/winner styles, status pulse line, settlement summary, autopilot footer. Replace content sources:
- Delete the `sec >= N` gating, text-rewriting regexes, and all literal bid/vote/telemetry content; render `runLog` (T+Xs from each entry's real `at`).
- Status line keyed off real `incident.status`; settlement card uses real values (no `|| 500`); handle `noop` and `failed` endings explicitly.
- Keep the `StrengthBars` export (used by `SlaLineChart.tsx`).

### 6. `HomePage.tsx`
- Run button keeps the KL→Penang relocation UX (sim inputs) but recovery goes through the backend-first store action with the intent built from that state; recovered metrics come from the real offer/session instead of literals; "Agent activity" feed derives from `runLog`/`incident.events` during a run; restored copy uses real numbers.
- `UserListPage.tsx`: compute KPI chips from the `DUMMY_USERS` array instead of literal strings.

### 7. Verification
- `node scripts/start-all.mjs` + `npm run trust:server` + `npm run frontend`; run the HomePage simulation → same narrative with real data (real bids, real gonka request IDs, real escrow/Walrus tx links, real audit card, real timings; Suiscan links resolve).
- Stop the backend → re-run: simulated fallback still renders the full narrative (no `sec`-scripting).
- DevPage "Run live" works without the SMS stall; fault demos still work; nav no longer shows Services/Truth; direct `/services`/`/truth` URLs redirect home; `tsc` build clean.

**Explicitly stays:** static UI labels (sender/tag names, step titles, footer copy), scenario fixture JSONs (inputs), `dummyUsers` list content. Follow-ups (out of scope): backend emitting raw Gonka reasoning in votes, a real subscribers API.
