# NetChain Workflow & zkLogin Diagnostics System

## Summary of Additions

We have added a comprehensive real-time diagnostic system across the frontend and backend to trace and debug every single step of the workflow from Google zkLogin to Gonka router decision to Sui testnet on-chain settlement.

### 1. Dedicated Diagnostics Page (`/#/logs`)
- Created [`frontend/src/pages/DebugLogsPage.tsx`](file:///c:/repository/NetChain/frontend/src/pages/DebugLogsPage.tsx).
- Added direct link in the top navigation bar (`Logs` tab) and route at `http://localhost:5173/#/logs`.
- **Live State Inspector**:
  - **Buyer Address**: Displays the active wallet address.
  - **Signing Mode**: Displays `zk` (non-custodial) vs `custodial-fallback`.
  - **Google Identity**: Displays email and sub claim.
  - **Testnet Epoch Check**: Fetches the live testnet epoch and checks if your session's `maxEpoch` is **VALID** or **EXPIRED**.
  - **Ephemeral Key Continuity Check**: Checks if the ephemeral key stored in your browser matches the key bound into your session (flags **MATCH** vs **MISMATCH**).
  - **Groth16 Proof Components**: Verifies `proofPoints`, `issBase64Details`, and `headerBase64`.
- **Workflow Log Stream**:
  - Filterable by level (`ALL`, `ERROR`, `WARN`, `SUCCESS`, `INFO`).
  - Searchable by step name or payload content.
  - Formatted JSON inspector for every step.
  - "Copy All Logs JSON" button for one-click debugging export.

### 2. Frontend Workflow Logger
- Created [`frontend/src/services/logger.ts`](file:///c:/repository/NetChain/frontend/src/services/logger.ts).
- Instrumented the entire pipeline:
  - `EPOCH_RESOLVED` / `EPOCH_FALLBACK`
  - `ZK_LOGIN_BEGIN` (logs ephemeral pubkey, maxEpoch, nonce)
  - `ZK_LOGIN_COMPLETE` (logs Google claims, derived salt, derived address)
  - `ZK_PROOF_REQUEST` & `ZK_PROOF_SUCCESS` (logs payload sent to Mysten prover and proof structure returned)
  - `RECOVERY_COMMIT_START` (logs incident ID, selected provider, agreement amount)
  - `PAYMENT_COIN_RESOLVED` (logs Circle USDC coin ID and type)
  - `COMMIT_PTB_BUILT` (logs unsigned transaction bytes generated by trust server)
  - `ZK_SIGN_PREPARE` (checks key match, address seed, maxEpoch validity)
  - `ZK_SIGNER_VALIDATED` (validates address derivation matches sender)
  - `SUI_EXECUTE_TX_REQUEST` (logs RPC request parameters)
  - `SUI_EXECUTE_TX_SUCCESS` / `SUI_EXECUTE_TX_REJECTED` / `SUI_EXECUTE_TX_ERROR` (captures full on-chain response/error)

### 3. Backend Telemetry Mirror (`server.js`)
- Added `POST /api/zklogin/log` to [`src/zklogin/server.js`](file:///c:/repository/NetChain/src/zklogin/server.js).
- Any event logged in the browser is automatically echoed with ANSI color formatting straight into your PowerShell terminal running `npm run zklogin:server`.
- In-memory ring buffer available via `GET /api/zklogin/logs`.

## How to Test and View Logs

1. **Restart your zkLogin server in PowerShell (Pwsh 3):**
   In the PowerShell window running `npm run zklogin:server`:
   - Press `Ctrl + C`
   - Run:
     ```powershell
     npm run zklogin:server
     ```
2. **Open the Diagnostics Page:**
   - In your browser, navigate to:
     `http://localhost:5173/#/logs` (or click **Logs** in the top navigation).
   - Check the **Live zkLogin Session Status** card:
     - Is the testnet epoch showing $\ge 1211$?
     - Is your proof maxEpoch showing green `VALID`?
     - Is your ephemeral key showing green `MATCH`?
3. **Log Out & Log In Fresh:**
   - If either check is red or expired, go to Profile $\rightarrow$ **Log Out**.
   - Click **Continue with Google** to sign in.
   - Return to `http://localhost:5173/#/logs` and observe all login & proof events in the log table!
4. **Execute Run Live:**
   - Go to `http://localhost:5173/#/dev`.
   - Click **Run Live**.
   - Watch the logs stream in real-time in both:
     - Your PowerShell terminal (`pwsh 3`).
     - The browser diagnostics page (`http://localhost:5173/#/logs`).
